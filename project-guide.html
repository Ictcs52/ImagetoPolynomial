1. โครงงานนี้ทำอะไร?

POLYART — Polynomial Art Recording Tool เป็นเว็บแอปพลิเคชันที่รับภาพลวดลายหรือภาพเส้น ตรวจหาจุดและรูปทรงสำคัญ แล้วแปลงเป็นชุดสมการทางคณิตศาสตร์ที่สามารถคัดลอกไปทดลองวาดกราฟต่อได้ แนวคิดของโครงงานคือเชื่อมโยง ศิลปะ วัฒนธรรม คณิตศาสตร์ และการเขียนโปรแกรม

5. ลำดับการทำงานของระบบจริง

เลือกภาพ→ตรวจไฟล์→Canvas→Sobel Edge→สกัดพิกัด→ขาว–ดำ→ค้นหารูปทรง→สร้างสมการ→แสดง/ดาวน์โหลด
ขั้นตอนฟังก์ชันหลักสิ่งที่เกิดขึ้น
1. รับไฟล์handleFileSelect()ตรวจชนิด JPG/PNG และขนาดไม่เกิน 16 MB
2. แสดงตัวอย่างloadImagePreview()FileReader อ่านไฟล์เป็น Data URL และเก็บขนาดภาพ
3. เริ่มประมวลผลprocessImage()ควบคุมงานทุกขั้นและอัปเดต Progress
4. ตรวจขอบperformMultiLevelEdgeDetection()วาดภาพบน Canvas แล้วเรียก Sobel Filter
5. สกัดพิกัดextractRealCoordinates()เลือกจุดขอบที่ผ่าน threshold และแปลงเป็นแกนคณิตศาสตร์
6. สร้างสมการgenerateAdvancedEquations()ใช้ Direct Pixel Mapping เป็นเส้นทางหลัก ก่อนใช้วิธีวิเคราะห์อื่นเป็น fallback
7. แสดงผลdisplayAdvancedResults()แสดงสถิติ รายการสมการ ปุ่มคัดลอก และดาวน์โหลด

6. ระบบมองภาพอย่างไร?

6.1 Grayscale และภาพขาว–ดำ

ค่าสีแดง เขียว น้ำเงิน ถูกแปลงเป็นความสว่างโดยให้น้ำหนักไม่เท่ากัน เพราะสายตามนุษย์รับรู้แต่ละสีต่างกัน

Gray = 0.299R + 0.587G + 0.114B

จากนั้นใช้ threshold 128: ค่าสว่างมากกว่า 128 เป็นสีขาว มิฉะนั้นเป็นสีดำ

6.2 Sobel Edge Detection

Sobel ใช้ kernel ขนาด 3×3 วัดการเปลี่ยนแปลงความสว่างแนวนอนและแนวตั้ง ได้ค่า Gx และ Gy

Edge magnitude = √(Gx² + Gy²)

จุดที่ magnitude มากกว่า threshold 100 ถูกพิจารณาเป็นจุดขอบ

ข้อควรระวังในการนำเสนอ: แม้ข้อความอธิบายเก่าบางตำแหน่งในหน้าเว็บใช้คำว่า “Canny” แต่โค้ดเส้นทางปัจจุบันเรียก applySobelFilter() และใช้ Sobel kernels โดยตรง จึงควรตอบว่าใช้ Sobel Operator

7. การแปลงพิกเซลเป็นพิกัดคณิตศาสตร์

พิกัดภาพ

จุดกำเนิดอยู่มุมซ้ายบน ค่า x เพิ่มไปทางขวา และ y เพิ่มลงด้านล่าง

พิกัดคณิตศาสตร์

ระบบย้ายจุดกำเนิดไปกลางภาพ ค่า x เพิ่มไปทางขวา และ y เพิ่มขึ้นด้านบน จึงต้องกลับเครื่องหมายแกน y

scale = min(width, height) / 20
mathX = (pixelX − width/2) / scale
mathY = (height/2 − pixelY) / scale
ทำไมต้องหารด้วย scale? เพื่อย่อพิกัดภาพหลายร้อยหรือหลายพันพิกเซลให้อยู่ในช่วงประมาณ −10 ถึง 10 ซึ่งนำไปวาดบนระบบพิกัดได้สะดวก

8. สมการที่ระบบสามารถสร้าง

รูปแบบตัวอย่างแนวคิดใช้แทนอะไร
จุด/วงกลมขนาดเล็ก(x−h)²+(y−k)²=r²จุดสำคัญจากพิกเซลเข้ม
เส้นตรงy=mx+b หรือ x=cขอบแนวนอน แนวตั้ง และแนวทแยง
พาราโบลา/พหุนามy=ax²+bx+cเส้นโค้งที่ประมาณได้ด้วย polynomial
วงกลมและวงรี(x−h)²/a²+(y−k)²/b²=1รูปทรงปิดหรือส่วนโค้ง
ตรีโกณมิติy=A sin(Bx+C)+Dรูปแบบคลื่นหรือส่วนโค้งที่มีคาบ
สมการมีโดเมนy=mx+b {a≤x≤b}จำกัดให้แสดงเฉพาะช่วงที่พบในภาพ

Polynomial Regression ทำงานอย่างไร?

เมื่อใช้ส่วน Polynomial Regression ระบบสร้าง Vandermonde Matrix จากค่า x แล้วหาสัมประสิทธิ์ด้วยวิธี Least Squares/Normal Equations และ Gaussian Elimination

y ≈ a₀ + a₁x + a₂x² + … + aₙxⁿ
(AᵀA)c = Aᵀy

หมายเหตุ: เส้นทางทำงานปัจจุบันให้ Direct Pixel Mapping ทำงานก่อน ดังนั้น Polynomial Regression ไม่ได้เป็นวิธีเดียวและไม่จำเป็นต้องเป็นผลลัพธ์หลักของทุกภาพ

9. อ่านผลลัพธ์อย่างไรให้ถูกต้อง

จำนวนสมการ

จำนวนองค์ประกอบสมการที่ระบบสร้าง ไม่ใช่จำนวนรูปทรงจริงทั้งหมดในภาพ

จำนวนจุดข้อมูล

จำนวนจุดขอบที่สกัดได้หลัง sampling/filtering ขึ้นกับขนาด ความคมชัด และรายละเอียดของภาพ

ความแม่นยำ

ในโค้ดปัจจุบันบางสมการกำหนดคะแนนจากกฎของตัวสร้างสมการ เช่น 0.99 จึงยังไม่ควรใช้เป็นหลักฐานว่าเหมือนภาพ 99%

R², RMSE และ MAE: โค้ดมีฟังก์ชันคำนวณค่าสถิติสำหรับ Polynomial Regression แต่หน้าผลลัพธ์หลักปัจจุบันเน้นชุดสมการจาก Direct Pixel Mapping จึงไม่ควรอ้างว่าทุกสมการผ่านการประเมินด้วย R²/RMSE/MAE
ควรพูดไม่ควรพูด
ระบบสร้างสมการเพื่อประมาณองค์ประกอบของภาพระบบหาสมการต้นฉบับที่ถูกต้องแน่นอน
คะแนนที่แสดงเป็นค่าประเมินภายในโปรแกรมความแม่นยำผ่านการทดสอบแล้ว 99%
ผลขึ้นกับคุณภาพและชนิดของภาพใช้ได้แม่นยำเท่ากันกับภาพทุกชนิด

11. แนวทางทดสอบโครงงานอย่างเป็นระบบ

ชุดภาพทดสอบที่ควรเตรียม

  1. เส้นตรงแนวนอน แนวตั้ง และแนวทแยง
  2. วงกลม วงรี และพาราโบลา
  3. ลายเส้นขาว–ดำที่คมชัด
  4. ภาพเดียวกันที่มีความละเอียดต่างกัน
  5. ภาพมี noise ภาพเบลอ และพื้นหลังซับซ้อน
  6. ภาพสีอ่อนบนพื้นหลังอ่อน เพื่อทดสอบกรณีที่ขอบไม่ชัด
สิ่งที่วัดวิธีวัดที่แนะนำ
ตรวจพบรูปทรงหรือไม่นับภาพที่ตรวจชนิดรูปทรงหลักได้ถูกต้องเทียบกับภาพทั้งหมด
ความใกล้เคียงของเส้นสุ่มจุดบนเส้นผลลัพธ์และวัดระยะถึงขอบภาพเฉลี่ย
เวลาในการประมวลผลจับเวลาตั้งแต่กดสร้างสมการจนแสดงผล แยกตามขนาดภาพ
ความพึงพอใจผู้ใช้แบบประเมินความง่าย ความชัดเจน และประโยชน์ต่อการเรียนรู้
ถ้าต้องการกล่าวว่า “แม่นยำ” ในอนาคต: ต้องกำหนดชุดข้อมูลทดสอบ เกณฑ์คำตอบที่ถูกต้อง และสูตรวัดผลให้ชัดเจนก่อน แล้วจึงรายงานค่าจากการทดลองจริง

ข้อจำกัดผลกระทบ
Threshold คงที่ค่า 100 สำหรับขอบและ 128 สำหรับขาว–ดำอาจไม่เหมาะกับภาพทุกสภาพแสง
ภาพซับซ้อนพื้นผิว สี เงา และเส้นจำนวนมากทำให้เกิดจุดหรือสมการที่ไม่ต้องการ
รูปทรงหลายค่า y ต่อ xPolynomial แบบ y=f(x) เพียงสมการเดียวแทนวงกลมหรือเส้นตั้งได้ไม่ครบ จึงต้องใช้สมการชนิดอื่นและ domain
คะแนน accuracyบางค่าถูกกำหนดเชิง heuristic ยังไม่ใช่ผล validation จาก ground truth
ประสิทธิภาพการสแกนทุกพิกเซลและเปรียบเทียบจุดจำนวนมากอาจช้ากับภาพขนาดใหญ่
การประมาณสมการที่ได้อาจแทนโครงร่างสำคัญ แต่ไม่รักษารายละเอียด สี และพื้นผิวทั้งหมด
ทำงานฝั่งผู้ใช้ประสิทธิภาพขึ้นกับ Browser และอุปกรณ์ของผู้ใช้

13. แนวทางพัฒนาต่อ

Adaptive Threshold

เลือก threshold ตามความสว่างในแต่ละบริเวณ เพื่อรองรับภาพแสงไม่สม่ำเสมอ

Contour & Segmentation

ติดตามเส้นขอบเป็นกลุ่มต่อเนื่องก่อนฟิตสมการ ลดจุดรบกวนและสมการซ้ำ

วัดผลจริง

สร้างชุดทดสอบพร้อม ground truth และรายงาน precision, error หรือ similarity ที่นิยามชัดเจน

ปรับประสิทธิภาพ

ย่อภาพ ใช้ Web Worker หรือ sampling แบบปรับตัว เพื่อลดเวลาประมวลผล

แก้ไขสมการ

ให้ผู้ใช้เลือก ลบ รวม และปรับพารามิเตอร์ของสมการก่อนส่งออก

ส่งออกเพิ่ม

เพิ่ม JSON/CSV/SVG และสร้างลิงก์หรือรูปแบบที่นำเข้าโปรแกรมกราฟได้สะดวก

14. คำถามที่กรรมการมีโอกาสถาม

ทำไมถึงทำโครงงานนี้?

ต้องการเชื่อมโยงศิลปะกับคณิตศาสตร์ และลดความยากของการเริ่มสร้างสมการจากลวดลายด้วยตนเอง โดยใช้ภาพเป็นข้อมูลตั้งต้น

ระบบใช้ AI หรือไม่?

เวอร์ชันปัจจุบันไม่ใช่ Generative AI หรือ Deep Learning แต่ใช้ Computer Vision แบบอัลกอริทึม การวิเคราะห์พิกเซล การตรวจขอบ การตรวจรูปทรง และการประมาณสมการ

ใช้ Canny หรือ Sobel?

โค้ดที่ทำงานจริงใช้ Sobel Operator ผ่านฟังก์ชัน applySobelFilter() เพื่อหาค่า gradient ในแนว x และ y

ทำไมต้องแปลงเป็นภาพขาว–ดำ?

เพื่อลดความซับซ้อนจากหลายสี ให้ระบบแยกส่วนที่เป็นเส้นเข้มกับพื้นหลังได้ง่ายขึ้น

ทำไมต้องกลับแกน y?

พิกัดภาพมีค่า y เพิ่มลงด้านล่าง แต่กราฟคณิตศาสตร์มีค่า y เพิ่มขึ้นด้านบน จึงต้องกลับทิศในการแปลงพิกัด

ทำไมไม่ใช้สมการพหุนามเพียงสมการเดียว?

ภาพหนึ่งภาพอาจมีเส้นตั้ง วงกลม รูปทรงปิด และหลายเส้น ซึ่งไม่สามารถแทนด้วย y=f(x) สมการเดียวได้ จึงใช้สมการหลายประเภทและจำกัด domain

Least Squares คืออะไร?

เป็นวิธีหาค่าสัมประสิทธิ์ที่ทำให้ผลรวมกำลังสองของความคลาดเคลื่อนระหว่างจุดข้อมูลกับเส้นสมการมีค่าน้อยที่สุด

ค่า 99% บอกว่าเหมือนภาพ 99% หรือไม่?

ยังไม่ใช่ เพราะบางสมการกำหนดคะแนนจากกฎภายในโค้ด ต้องมีชุดทดสอบและ metric ที่ชัดเจนก่อนจึงจะเรียกเป็นความแม่นยำที่ผ่านการประเมินได้

ระบบเก็บภาพของผู้ใช้หรือไม่?

ระบบทำงานใน Browser และไม่มี Backend/ฐานข้อมูล ภาพถูกอ่านเพื่อประมวลผลบนอุปกรณ์ในรอบการใช้งานนั้น

ภาพแบบใดให้ผลดีที่สุด?

ภาพลายเส้นเข้มบนพื้นหลังอ่อน ขอบคม รูปทรงไม่ซ้อนกันมาก และไม่มีเงาหรือ noise มาก

จุดเด่นของโครงงานคืออะไร?

ใช้งานผ่านเว็บได้ทันที ไม่ต้องส่งข้อมูลไป Server เชื่อมโยงหลายศาสตร์ และทำให้ผู้ใช้เห็นกระบวนการจากภาพไปสู่พิกัดและสมการอย่างเป็นรูปธรรม

ข้อจำกัดสำคัญที่สุดคืออะไร?

ผลลัพธ์ขึ้นกับคุณภาพภาพและ threshold และคะแนนความแม่นยำปัจจุบันยังไม่ได้ validation ด้วยชุดข้อมูลมาตรฐาน

ถ้าพัฒนาต่อจะทำอะไรเป็นอันดับแรก?

สร้างชุดภาพทดสอบที่มีคำตอบอ้างอิง ปรับ adaptive threshold และ contour tracking แล้ววัดความคลาดเคลื่อนของเส้นผลลัพธ์อย่างเป็นระบบ

ทำไมเลือกทำเป็นเว็บ?

ผู้ใช้เปิดได้จากหลายอุปกรณ์ ไม่ต้องติดตั้งโปรแกรม และเผยแพร่ผ่าน GitHub Pages ได้ง่าย ขณะเดียวกัน Canvas และ JavaScript รองรับการประมวลผลภาพฝั่งผู้ใช้

15. บทพูดสรุปสำหรับนำเสนอ

“โครงงาน POLYART เป็นเว็บแอปพลิเคชันที่เชื่อมโยงศิลปะ คณิตศาสตร์ และการเขียนโปรแกรม ผู้ใช้อัปโหลดภาพลายเส้นในรูปแบบ JPG หรือ PNG ระบบจะอ่านพิกเซลด้วย HTML5 Canvas แปลงค่าสีเป็นความสว่าง ตรวจหาขอบด้วย Sobel Operator และแปลงตำแหน่งพิกเซลเป็นพิกัดคณิตศาสตร์ จากนั้นระบบวิเคราะห์จุดและรูปทรงเพื่อสร้างชุดสมการ เช่น เส้นตรง วงกลม วงรี และพหุนาม พร้อมกำหนด domain ให้แสดงเฉพาะช่วงที่เกี่ยวข้อง ผลลัพธ์สามารถคัดลอกหรือดาวน์โหลดไปทดลองต่อได้ ระบบทำงานภายใน Browser โดยไม่ต้องมี Backend อย่างไรก็ตาม สมการที่ได้เป็นการประมาณลักษณะสำคัญของภาพ ผลจึงขึ้นกับความคมชัดและความซับซ้อนของภาพ และเรามีแผนพัฒนาชุดทดสอบกับการวัดความคลาดเคลื่อนให้เป็นระบบมากขึ้น”
